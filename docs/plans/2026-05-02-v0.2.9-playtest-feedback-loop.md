# v0.2.9 闭门试玩入口与反馈闭环计划

> **给 Hermes：** 这是 v0.2.8 发布后的低风险运营/文档切片。保持外科手术式修改，不改玩法、不改打包逻辑；目标是让试玩者能下载、启动、反馈，让开发者能把反馈转成下一轮优先级。

**目标：** 把 `v0.2.8-demo` 从“已发布”推进到“可以稳定分发给 5-10 名闭门试玩者并回收可执行反馈”。

**架构：** 只改文档与发布入口：README、试玩说明、反馈汇总模板、路线图索引。代码和资源治理原本作为后续 v0.2.9/v0.2.10 切片；当前已追加完成若干低风险资源治理切片，需要把分发 QA 与 roadmap 状态重新对齐。

**技术栈：** Markdown、GitHub Releases、现有 npm check/build gate。

---

## 1. 基线

- 当前发布：`v0.2.8-demo`
- Release：<https://github.com/zhuowater/Night-Patrol/releases/tag/v0.2.8-demo>
- Commit：`597ba7b`
- 已发布资产：Linux x64、macOS arm64、Windows x64。
- 本轮重点：下载入口、系统拦截说明、反馈汇总方法、下一步决策门槛。

## 2. 非目标

本切片不做：

- 新敌人、新卡牌、新事件、新视频；
- 平衡大改；
- Electron / GitHub Actions 工作流重写；
- 资源压缩脚本或首屏分包；
- Steam / 商店页 / 商业发行准备。

这些工作原本保留给反馈回流后的 `v0.2.9` 后半段或 `v0.2.10`。截至当前，资源审计/优化与首屏分包已经完成一轮工程切片；仍不把新内容扩展纳入本计划。

## 2.1 后续追加完成的工程切片

本计划创建后，仓库已继续完成以下低风险工程切片：

- `assets:audit`：runtime/generated/dist 三种视图、Top assets、类型/区域占比与预算违规。
- `assets:optimize`：WebP/压缩 MP4/压缩音频，支持 `--dry-run`、`--check`、`--force` 与 ffmpeg 依赖检查。
- `assets/optimized`：UI/BGM 入口已引用 optimized，`assets/generated` 保留为源素材诊断。
- Lazy chunks：`CinematicScreen` 与非首屏 `RunScreens` 已拆为动态 chunk；Phaser vendor chunk 仍大，但已是独立 vendor 警告。

因此 v0.2.9 当前不要再回到旧 Sprint checklist，而应先完成闭门试玩分发 QA，收集真实反馈后再决定下一轮 P0/P1。

**目标：** 试玩者不用懂 GitHub Release 命名，也知道该下载哪个文件。

**文件：**

- 修改：`README.md`

**步骤：**

3. 加 Windows SmartScreen、macOS 未公证、Linux AppImage 权限提示。
4. 把“当前计划提供”改成“当前已发布资产”。
5. 修正操作方式里“拖到敌人/玩家区域”的旧表述，和 v0.2.8 的“点击或拖出手牌区施放”一致。
