# v0.2.10「可学习失败」开发计划

> **给 Hermes：** 后续实现请使用 `subagent-driven-development` 或逐任务 TDD 执行；每个任务完成后运行对应检查，不要把新内容扩展混进本版本。

**Goal:** 把 `v0.2.9-demo` 从“能玩完但失败不可学习”推进到“玩家每局结束后知道为什么输/赢、下一局该改什么”，为真实 5-10 人闭门试玩准备更高质量的反馈入口。

**Architecture:** 不扩敌人/卡牌/章节，优先补状态记录、复盘 UI、事件补偿与短视口层级。核心做法是在 `GameState` 增加轻量 run telemetry，由 engine 在路线/战斗/奖励/事件节点记录关键摘要，EndScreen 读取并展示“本局 SOC 复盘”。事件收益只做小范围补强，避免大平衡重写。

**Tech Stack:** React 18、TypeScript、Vite、Electron、现有 engine modules、现有 `npm run check` / `npm run build` gates。

### 0.1 产品判断

5 人模拟试玩中 **1/5 通关，4/5 死于 Boss**。问题不应被粗暴理解为“Boss 太难”，因为四个死亡样本死因不同：

- 新手：过度防守，Boss 长战 26 回合耗死；
- 肉鸽玩家：贪 Elite，Boss 入场血线不足；
- 安全玩家：多走事件，工具/构筑补偿不足；
- hard 玩家：高风险路线 Boss 前 9 血，两回合死亡。

因此 v0.2.10 的核心不是削 Boss，也不是加内容，而是让失败变得**可解释、可学习、可复盘**。

### 0.2 本版本非目标

- 新章节、新 Boss、新敌人、新卡牌大包；

- 多敌人、多角色、存档系统。

### Task 3：记录战斗摘要与死亡原因基础推断

**Step 3: 在伤害结算处更新 maxDamageDealt / maxDamageTaken**

- 玩家对敌伤害时更新 `maxDamageDealt`；
- 敌人/事件导致战斗内玩家掉血时更新 `maxDamageTaken`。

**Step 4: 战斗结束时 append summary**

```ts

  floor: state.floor,
  type: combat.type,
  enemyName: combat.enemy.name,
  startHp: combat.summary?.startHp ?? player.hp,
  endHp: player.hp,
  turns: combat.turn,
  maxDamageDealt: combat.summary?.maxDamageDealt ?? 0,
  maxDamageTaken: combat.summary?.maxDamageTaken ?? 0,
});
```

**Step 5: causeHint 最小规则**

gameover 时生成 `state.runSummary.causeHint`：

```ts
function inferRunCauseHint(state: GameState) {
  const boss = state.runSummary.combats.find((combat) => combat.type === "boss");
  const eliteCount = state.runSummary.route.filter((route) => route.nodeType === "elite").length;
  const eventCount = state.runSummary.route.filter((route) => route.nodeType === "event").length;
  const bossEntryHp = state.runSummary.bossEntryHp ?? state.player?.hp ?? 0;
  const bossEntryMaxHp = state.runSummary.bossEntryMaxHp ?? state.player?.maxHp ?? 1;

  if (boss && boss.turns >= 18) return "Boss 战拖入长线，说明牌组缺少收口爆发或过度防守。";
  if (boss && bossEntryHp / bossEntryMaxHp <= 0.25) return "进入核心域控前防线过低，前序路线风险已经透支。";
  if (eventCount >= 4 && eliteCount === 0) return "事件路线偏多但构筑补偿不足，Boss 前缺少关键工具或爆发。";
  if (eliteCount >= 3) return "高危入侵收益高但代价重，本局属于贪高危后的血线失败。";
  return "攻击链突破窗口；下一局优先检查路线风险、Boss 入场血线和构筑短板。";
}
```

## 5. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Telemetry 过度设计 | 拖慢版本，污染 engine | 只记录 summary，不做完整事件流数据库 |
| 复盘 UI 信息过载 | 解决失败不可学习时又制造新负担 | 默认显示 5-6 个关键块，详细日志折叠 |
| 事件补偿导致数值变简单 | 误判 Boss 难度 | 只补方向，不大幅加血/加稀有工具；保留 `check:playtest-run` |
| 直接削 Boss 掩盖真实问题 | 反馈质量下降 | v0.2.10 不削 hard，不大调 normal Boss |
| 文档与 release 状态再分叉 | 试玩者下载/反馈混乱 | roadmap 顶部显式指向 v0.2.10 计划与反馈表 |
