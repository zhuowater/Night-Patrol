# v0.2.8 首次跑局引导与信息架构实施计划

> **给 Hermes：** 直接在当前会话按小切片执行。只有独立审计/复核任务才使用 subagent-driven-development。所有改动保持外科手术式、面向发布，并在每个切片后验证。

**目标：** 把 v0.2.7 闭门试玩版从“系统已经看得见”推进到“第一次玩的玩家知道第一局该做什么”：加入渐进式首次引导，重排战斗/奖励信息层级，统一资源语言，并补齐发布与试玩验证闭环。

**架构：** 保持现有 React + TypeScript + Vite + Electron 结构。v0.2.8 不扩内容量。基于已有预览能力（`previewAttackChain`、`previewCardEffect`、卡牌威胁提示、事件/商店/升级预览）叠一层轻量 first-run guidance；通过渐进披露折叠专家细节，降低视觉竞争。避免大规模引擎重写或完整战斗屏重做。

**技术栈：** React 18、TypeScript、Phaser 3 懒加载战斗舞台、Vite、Electron、Node/tsx 校验脚本。

**当前基线：**

- 包/发布基线：`v0.2.7-demo` / package version `0.2.7`。
- Release URL：`https://github.com/zhuowater/Night-Patrol/releases/tag/v0.2.7-demo`。

- 上一版计划：`docs/plans/2026-05-02-v0.2.7-player-perception-polish.md`。

**v0.2.8 应继承的报告判断：**

- v0.2.7 已经是一个真正可闭门试玩的版本，并且安全机制有差异化。
- 下一个瓶颈不是内容不足，而是第一局认知负担过高。
- 已经成立的强机制包括：攻击链态势、C2 信标、IOC、噪声、凭据/勒索反制、奖励/构筑提示。
- 最大风险：新玩家在知道“第一步该做什么”之前，就被大量专业信息压住。

## 1. v0.2.8 产品原则

v0.2.8 只回答一个问题：

> 第一次玩的玩家，是否能在第一局里理解“这回合我该先做什么、为什么这么做、做完之后发生了什么”？

优先级：

1. **首次跑局引导**：第一战、首次 C2、首次噪声、首次奖励。
2. **战斗信息层级**：敌方意图 → 推荐行动 → 手牌 → 专家级攻击链细节。
3. **资源语言治理**：让卡牌费用、回合能量、临时算力到底是不是同一概念变得明确。
4. **奖励决策聚焦**：候选卡牌成为第一视觉目标，日志/工具说明不再抢注意力。
5. **地图渐进披露**：当前可选节点优先，远端未来节点弱化。
6. **发布/试玩就绪**：更新试玩说明、反馈表、smoke checklist、版本号，并跑完整 gate。

## 2. 非目标

除非出现阻断闭门试玩的 bug，v0.2.8 不做以下事项：

- 大量新增卡牌、敌人、事件、视频或音频。
- 在缺少真实外部失败率数据前，大幅重平衡 normal/hard。
- 做分支教程战役或完整 onboarding story mode。
- 加多敌人目标选择。
- 加存档、元进度、账号、遥测后端或 Steam/发行平台工作。
- 替换 Phaser、音频或 Electron 打包架构。

## 4. 实施任务

### Task 1：加入首次引导状态

**目标：** 记录玩家是否已经看过关键首次引导，不引入持久化或账号状态。

**文件：**

- 修改：`src/game/types.ts`
- 修改：`src/game/engine/state.ts` 或当前状态初始化位置
- 测试：如果接入简单，在 `scripts/check-engine-scenarios.ts` 加状态 fixture 断言；否则依赖类型检查/build gate

**目标最小状态：**

```ts
export type GuidanceCueId = "firstCombat" | "firstC2" | "firstNoise" | "firstReward";

export interface GuidanceState {
  seen: Partial<Record<GuidanceCueId, boolean>>;
}

export interface GameState {
  // existing fields
  guidance?: GuidanceState;
}
```

**步骤：**

1. 增加 `GuidanceCueId` 和 `GuidanceState` 类型。
2. 开始新 run 时初始化 `game.guidance = { seen: {} }`。
3. 如有必要，在 state/game transaction 附近加两个小 helper：
   - `hasSeenGuidance(game, id)`；
   - `markGuidanceSeen(game, id)`。
4. v0.2.8 保持会话内状态，不写 localStorage。
5. helper 要兼容旧状态里 `guidance` 缺失的情况。

**验证：**

```bash

npm run build
```

预期：两者都通过。

### Task 4：加入回合级推荐行动条

**目标：** 把卡牌级 hint 汇总成一条“当前最好先关注什么”，避免新玩家必须先读完所有卡。

**文件：**

- 修改：`src/game/engine/cardPreview.ts`
- 修改：`src/App.tsx`
- 修改：`src/styles.css`
- 测试：`scripts/check-engine-scenarios.ts` 或新建轻量 `scripts/check-card-preview.ts`

**目标 helper：**

```ts
export function recommendTurnAction(context: {
  combat: CombatState;
  player: PlayerState;
}): null | {
  title: string;
  reason: string;
  priority: "defense" | "counter" | "attack" | "setup";
};
```

**规则保持简单、确定性：**

1. 如果敌方即将攻击且当前防护不足，且有可打防御牌：推荐防御。
2. 如果 C2 需要 IOC 且有可打 IOC 牌：推荐 IOC 反制。
3. 如果勒索需要算力且有可打算力牌：推荐补算力。
4. 如果敌人已有 IOC 且 payoff 牌可打：推荐兑现 IOC。
5. 否则推荐压低血量或建立抽牌/资源。

**步骤：**

1. 基于现有 hand/card metadata 实现 helper。
2. 如测试接入低成本，至少加 defense vs attack、IOC vs C2 两个断言。
3. 在手牌/情报边界渲染 `.turn-recommendation`。
4. 文案明确这是引导，不是强制最优解：使用 `值班建议`，不要写“最佳操作”。
5. 如果和 first-run cue 重复太多，可以让 first-run cue 引用该推荐，而不是重复一大段。

**验证：**

```bash
npm run check:engine-scenarios
npm run build
```

浏览器 smoke：

- 第一战遇到 incoming attack 时显示防御/行动建议。
- C2 战斗且手中有 IOC 牌时显示 IOC 反制建议。

### Task 6：统一资源命名与 tooltip

**目标：** 消除卡牌费用、回合 energy/orb、临时 compute/算力之间的混淆。

**文件：**

- 修改：`src/game/content.ts`
- 修改：`src/ui/cards.tsx`
- 修改：`src/App.tsx`
- 修改：`src/styles.css`
- 可选修改：`docs/playtest/v0.2.8-feedback-form.md`

**决策：**

除非代码检查证明确实存在两个不同资源，否则玩家可见层统一把卡牌费用和每回合资源称为：**响应算力**。

统一标签：

- HUD/orb：`响应算力 3/3`
- 卡牌费用：`消耗 1 响应算力`
- 如果是同一资源池的获得效果：`获得 +1 响应算力`
- 如果确实存在单独的临时/持续资源：明确命名为 `临时算力`，并加 tooltip。

**步骤：**

1. 搜索玩家可见文案中的 `能量`、`energy`、裸 `算力`、`incense`、`cost`。
2. 替换为一致术语。
3. 在资源展示附近加 tooltip/help：
   - `响应算力：本回合可用于打出响应牌，回合开始刷新。`
4. 只更新玩家可见的 card preview 文案。
5. 非必要不改内部变量名；保持改动外科手术式。

**验证：**

```bash

```

浏览器 smoke：

## 8. 已知风险与护栏

- **风险：** 教学 cue 变成烦人的弹窗。  
  **护栏：** 使用 inline/dismissible cue，不做 modal tutorial，不强制玩家操作。

- **风险：** 推荐行动条变成伪“策略 AI”。  
  **护栏：** 只使用确定性、显而易见的规则；标签用 `值班建议`，不用“最佳操作”。

- **风险：** 折叠专家细节隐藏本作差异化。  
  **护栏：** readiness chips 与行动文案保持可见；只折叠长专业 prose。

- **风险：** 资源改名造成代码 churn。  
  **护栏：** 先改玩家可见文案；内部变量名可以以后再治理。

- **风险：** 奖励/日志重排破坏现有布局。  
  **护栏：** 只重排 markup 和 CSS，不改 reward generation。

- **风险：** v0.2.8 滑向内容扩张。  
  **护栏：** 任何新增卡牌/敌人/视频需求，除非修阻断 bug，否则移到 v0.2.9。
