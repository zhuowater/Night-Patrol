# 《夜巡 SOC：边界告警》网络安全改编设计

> 基于 `Night-Patrol` 当前第一关竖切 demo，将故事线、文案和素材系统从“志怪夜巡”改为“赛博夜巡 + 企业安全响应”。
>
> 日期：2026-04-30
> 状态：设计待确认，未进入实现。

## 1. 设计结论

采用 **“赛博夜巡东方风”**：保留原作“夜巡、残灯、黑夜、异物逼近”的气质，但把所有妖怪、符箓、香火、荒庙替换为网络安全语义。

玩家身份从“游方夜巡人”变为“夜班 SOC 响应员 / 数字夜巡人”。敌人不是传统妖物，而是被可视化为数字异形的攻击活动：端口扫描器、钓鱼载荷、僵尸进程、横向移动脚本、C2 操作员、凭据窃取器、勒索核心。

核心玩法不在第一阶段重写，先完整换皮：

- 保留当前路线、战斗、奖励、事件、商店、休整、Boss 流程。
- 保留数值和卡牌效果，只替换命名、文案、视觉资产、README 和应用包装。
- 等网络安全主题版完整可玩后，再进入安全机制深化。

## 4. 世界观

企业内网被抽象为一条午夜巡检路线。每个节点是一次安全决策：追踪攻击、处理告警、进入工具库、维护规则、加固资产，最终阻断一场针对核心域控的入侵。

场景不做真实 SIEM 仿真，而是做“游戏化 SOC 控制台”：

- 左侧是夜色与数据流。
- 中央是攻击实体的半透明数字形态。
- 下方是卡牌响应动作。
- 背景是服务器机房、拓扑网格、日志瀑布、告警红线。

氛围关键词：

- 东方夜巡
- 暗色 SOC 大屏
- 霓虹青、告警红、电路金
- 半透明数字妖影
- 日志流、拓扑图、数据符箓、命令行残影

## 14. 实施阶段

### Phase 1：完整主题换皮

目标：不改机制，得到完整可玩的网络安全版本。

改动范围：

1. `package.json`：name、description、productName、appId。
2. `index.html`：title。
3. `electron/main.cjs`：窗口标题。
4. `README.md`：项目介绍、玩法、技术栈、授权说明。
5. `src/game/content.ts`：卡牌、遗物、敌人、节点、事件文案。
6. `src/game/engine.ts`：日志文案、路线行名、过场标题和描述。
7. `src/App.tsx`：标题页、HUD、地图说明、结算面板、about 文案。
8. `src/phaser/CombatStage.tsx`：资产引用先不变，后续替换对应图片内容。
9. 生成并替换 P0 静态资产。
10. `npm run build` 验证。
11. 浏览器实际打开验证：标题页、地图、战斗、结算 fallback。

验收标准：

- 页面中不再出现主要志怪世界观文案，如“荒庙、妖、香火、城隍、山君”等，除非作为内部文件名未暴露。
- 一局流程仍然能从标题页进入地图和战斗。
- `npm run build` 通过。
- 视觉上已经是网络安全主题，不是志怪素材残留。

### Phase 2：安全机制深化

目标：让玩法更像安全响应，而不只是换皮。

候选改动：

- 噪声告警可被“降噪过滤”清理或转化。
- IOC 标记影响更多卡牌分支。
- Boss 引入“加密倒计时”或“核心资产暴露”状态。
- 情报市场卖不同工具包。
- 事件加入业务连续性、误报、供应链、审计压力等安全决策。
- 卡牌奖励按“检测/响应/恢复/情报”分类。

### Phase 3：素材视频化

目标：用统一风格短视频增强结算与 Boss。

候选改动：

- 每个敌人 2–4 秒处置过场。
- Boss 8–15 秒阻断勒索核心过场。
- 视频播放失败时保留 poster fallback。
- 控制 dist 体积，优先 webm/压缩 mp4。

## 15. 风险与约束

1. **不要一次性重构引擎。** 当前任务是主题改造，先保玩法稳定。
2. **素材体积要控制。** 当前 dist 已约 87MB，新素材不能无节制膨胀。
3. **网络安全术语要真实但不硬核劝退。** 卡牌名可以专业，效果文本要短。
4. **避免变成企业安全产品 UI。** 这是游戏，不是 SIEM demo。
5. **避免黑客崇拜叙事。** 玩家视角是防守、响应、恢复。
6. **不要生成含真实品牌/厂商 logo 的素材。** 保持虚构企业和虚构工具。

## 16. 自检

- 没有未定占位或待办占位。
- 设计聚焦 Phase 1，不承诺一次性改机制。
- 文件路径对应当前仓库结构。
- 素材方案优先复用现有路径，降低代码风险。
- 网络安全主题采用防守视角，适合公开 demo。
