## 0. 总览结论

**可以发给 5-10 人闭门试玩，但现在最该收的问题不是“好不好玩”，而是：第一战是否仍过密、短视口是否舒服、Boss/通关复盘是否有记忆点。**

5 个模拟玩家里：4 人通关，1 名 hard 硬核玩家死于 Boss；这比“全员无脑通关”健康。新手在 story 档体验顺滑，但容易保守；卡牌玩家会主动贪 Elite 并感到构筑成立；安全从业者最吃题材；轻度小屏玩家能玩下去但 UI 负担明显；硬核玩家会认为 hard 路线选择有代价但 Boss 前血线预警不足。

## 2. 独立玩家反馈

### P1 普通新手玩家：Windows / 1366×768 / story

- **是否成功启动**：是。下载 zip 体积偏大但可接受；如果不是 Steam/itch 页面，普通用户会犹豫“下哪个文件”。
- **是否完整跑完**：是，胜利，终局 91/96。
- **路线**：边界告警 → 边界告警 → 情报市场 → 边界告警 → 边界告警 → 维护窗口 → 维护窗口 → 核心域控。
- **第一印象**：标题页最清楚的是“我是 SOC 值班的人，要接管夜班”；不清楚的是“这是不是恐怖/玄幻还是网络安全卡牌”。
- **第一战理解**：能跟着“建议响应”做，知道点卡牌和结束回合；但左侧攻击链态势基本不会读。
- **C2/噪声/资源**：噪声像坏牌能理解；IOC 大概懂；“响应算力/临时算力”仍会混。
- **最喜欢**：卡牌名和 SOC 词汇有新鲜感；story 档不惩罚，敢试。
- **最困惑**：奖励页三张牌每张都有“预计/取证/代价”，新手其实只想知道“推荐选哪张”。
- **一句话**：像一个有安全味的 Slay the Spire，但第一局还需要更明确地告诉我“选这张也可以”。
- **是否愿意玩下一版**：愿意，前提是有默认推荐路线/推荐奖励。

### P2 卡牌肉鸽玩家：Windows / 1920×1080 / normal

- **是否成功启动**：是。
- **是否完整跑完**：是，胜利，终局 51/84。
- **路线**：连续贪高危入侵，3 次 Elite + 1 次 Shop，路线风险收益成立。
- **玩法判断**：构筑核心能看出来：IOC、持续监控、沙箱引爆、降噪过滤、工具奖励串得起来。
- **第一战理解**：回合建议有用，但资深玩家希望能关掉或缩小，避免挡手牌。
- **奖励/商店**：奖励页聚焦比之前好；商店推荐理由仍不够“构筑诊断”，更像单卡说明。
- **Boss 感受**：Boss 有阶段压力，但“为什么我赢/为什么危险”的复盘不足。通关后希望看到本局核心 combo、最大伤害、噪声处理效率。
- **主要吐槽**：地图节点类型能读懂，但路线长远收益不够可视化；Elite 奖励工具很爽，但工具间强弱体感差距需要后续平衡。
- **一句话**：框架已经像一个能调数值的卡牌肉鸽了，下一步要给构筑复盘和更清楚的路线诱因。
- **是否愿意玩下一版**：愿意，会尝试 hard。

### P3 安全从业者：macOS arm64 / 1440×900 / normal

- **是否成功启动**：Release 有 macOS arm64 dmg/zip；模拟为可启动。
- **是否完整跑完**：是，胜利，终局 60/84。
- **路线**：事件偏好明显：异常事件 → 市场 → 异常事件 → 异常事件 → 维护 → Elite → Boss。
- **题材反馈**：C2、IOC、凭据、勒索核心、误报告警、供应链请求这些词非常加分；不是换皮 fantasy，而是确实在讲 SOC 夜班。
- **第一战理解**：安全术语玩家能读懂，但会挑剔：有些卡牌效果和真实 SOC 操作之间的抽象还可以更锋利。
- **事件反馈**：事件选择“预计结果”很关键；希望事件更像真实值班困境，例如业务方施压、误封风险、合规取证成本。
- **最喜欢**：攻击链反制日志和 IOC 反制窗口。
- **最困惑**：降权、临时算力这类偏游戏化词汇和安全语义之间还没完全合上。
- **一句话**：这是少见的“懂一点安全的人会愿意继续读文案”的安全卡牌 demo。
- **是否愿意玩下一版**：愿意，尤其想看更多真实 incident 剧本。

### P4 轻度策略/小屏玩家：Linux x64 / 1280×581 / normal

- **是否成功启动**：Linux zip 实际下载成功；AppImage/zip 资产存在。但 Linux 用户可能需要明确执行说明。
- **是否完整跑完**：是，胜利，终局 62/84。
- **路线**：倾向避开 Elite，多走事件/维护/商店，仍能通关。
- **UI 反馈**：标题页没问题；第一战在 1280×581 下能操作，但画面“满”，引导、左侧态势、手牌同时抢注意力。
- **短视口问题**：手牌 bottom 在 511-545，窗口高度 581，能看见但很贴底；中央值班建议对手牌阅读有遮挡。之前奖励页/事件页的短视口摩擦仍应作为闭门试玩重点观察项。
- **玩法反馈**：喜欢“建议响应”，但不想读专家态势；需要一个更明显的“只看这一句就能玩”的模式。
- **最困惑**：哪里是主线目标、哪里只是专家信息。小屏幕下玩家更容易误以为必须读完所有东西。
- **一句话**：能玩，但像在一块监控屏里塞了太多窗口。
- **是否愿意玩下一版**：可能；如果小屏布局更清爽会愿意。

### P5 硬核挑战玩家：Windows / 2560×1440 / hard

- **是否成功启动**：是。
- **是否完整跑完**：否，死于 Boss，终局 0/74。
- **路线**：边界告警 → 边界告警 → Elite → 边界告警 → Elite → Shop → Elite → Boss。
- **玩法判断**：hard 档贪 Elite 有明确代价：第 6 层前已掉到 21/74，第 7 层后 11/74，Boss 两回合死亡。这是好事，但需要更明确地告诉玩家“你已经在赌命”。
- **构筑反馈**：拿了 YARA、自动化响应、资产测绘、部署蜜罐、日志检索，进攻/工具很多，但防御与回血不足；这是合理失败。
- **主要问题**：失败复盘如果只显示输赢，会浪费 hard 玩家最想看的信息：哪一层开始崩、哪次 Elite 过贪、Boss 哪个倒计时没处理。
- **Boss 反馈**：Boss 压迫足够；但阶段转折和倒计时可以更戏剧化，最好有更强音效/视觉警报。
- **一句话**：hard 是能杀人的，但还缺一个让我服气的死亡报告。
- **是否愿意玩下一版**：愿意，前提是死亡复盘能帮助优化下一局。

## 3. 聚合问题分级

### P0 / 闭门试玩前最好修

1. **短视口信息遮挡与拥挤仍会污染反馈**  
   - 证据：1280×581 第一战可操作，但建议框、态势栏、手牌密集；手牌贴底。此前奖励/事件页也曾暴露短视口 CTA/候选牌可见性问题。  
   - 建议：短视口下缩小/可折叠“值班建议”，默认隐藏专家态势详情；奖励页保证三张候选牌效果摘要和选择 CTA 同屏。

2. **下载资产选择缺少面向玩家的一句话指引**  
   - 证据：Release 有 6 个资产，但普通玩家不一定知道 Windows 该下 exe 还是 zip、macOS 下 dmg 还是 zip、Linux 下 AppImage 还是 zip。  
   - 建议：Release body 顶部加“Windows 下载 .exe；macOS Apple 芯片下载 .dmg；Linux 下载 AppImage；打不开再用 zip”。

### P1 / 下一版高收益

1. **胜利/死亡复盘要升级成“本局 SOC 报告”**  
   - 卡牌玩家、hard 玩家、安全玩家都会需要：路线、关键构筑、最大威胁、噪声/C2/勒索处理、失败拐点。

2. **商店/奖励从单卡推荐升级为构筑诊断**  
   - 例如：“你现在 IOC 牌多但缺引爆”“噪声处理不足”“防护偏低，Boss 前建议补防御”。

3. **Boss 阶段与勒索倒计时再强化**  
   - hard 玩家已经会死，问题不是数值不够硬，而是死亡过程是否有戏剧性和可解释性。

### P2 / 可后置 polish

1. “响应算力 / 临时算力 / 降权”继续人话化。
2. 专家态势详情可加“新手不用读”的提示。
3. Linux/macOS 首次启动说明、签名/安全提示可写进 release note。

## 4. 设计/平衡/Bug/Polish 分类

### Design changes needed

- 新手奖励页需要“推荐选择/为什么”层，而不只是三张卡完整解释。
- 复盘必须支持玩家讲出自己的路线和构筑，否则肉鸽循环记忆点弱。
- 小屏幕默认信息层级应更激进：先玩，再展开专家信息。

### Balance adjustments

- hard 档贪 Elite 可导致 Boss 前 11/74 并死亡：目前看是合理风险，不建议削弱；建议先补死亡复盘。
- story 档 91/96 通关偏宽松，但符合首次试玩目标；不要急着调难。
- 工具奖励体感强弱待真实样本验证，尤其 Elite 工具是否“每件都像奖励”。

### Bug reports

- 本轮未发现阻塞性 bug。
- 非阻塞技术项：Vite chunk >500k warning；Linux 测试环境缺系统 unzip 命令但 Python zipfile 可正常读取，不是游戏 bug。

### Polish items

- Release 下载指引。
- Boss 音画警报、阶段提示。
- 事件 CTA 按钮感。
- 短视口下手牌/建议框间距。

## 5. 建议的真实闭门试玩问法

不要只问“好不好玩”。建议让 5-10 个真人按以下顺序反馈：

1. 下载时你有没有犹豫该点哪个文件？
2. 第一战你第一眼看哪里？是否知道这回合先做什么？
3. 你有没有读左侧专家态势？读了有帮助还是压力？
4. 奖励页你是认真读三张牌，还是随便选？
5. 商店有没有让你形成“我的构筑现在缺什么”的判断？
6. Boss 赢/输后，你能不能复述自己为什么赢/为什么输？
7. 如果只让你改一件事，是 UI 信息层级、术语、数值、还是内容量？
